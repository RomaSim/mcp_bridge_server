## 📖 Введение

MCP Bridge Server — это локальный мостовой сервис для [браузерного расширения MCP Bridge](https://github.com/WongJingGitt/mcp_bridge), который отвечает за управление и вызов инструментальных сервисов, следующих протоколу **[MCP (Model Context Protocol)](https://modelcontextprotocol.io)**.

Взаимодействуя с браузерным расширением через стандартный HTTP REST API, данный сервис в фоновом режиме динамически запускает, управляет и вызывает один или несколько процессов MCP-сервисов, а также统一 предоставляет их возможности веб-платформам AI (DeepSeek, Tongyi Qianwen, Tencent Yuanbao, Doubao и др.).

## ✨ Ключевые особенности

### 🎯 Основные возможности

- **Единое управление** — управление несколькими MCP-сервисами одновременно через простую JSON-конфигурацию.
- **Многоуровневое обнаружение инструментов** — двухэтапный механизм: сначала получение обзора сервисов, затем запрос деталей инструментов по требованию, что экономит токены.
- **Динамическая конфигурация** — поддержка горячей перезагрузки, применение новой конфигурации без перезапуска сервиса.
- **Кроссплатформенность** — автоматическая адаптация к Windows/macOS/Linux, конфигурация хранится в стандартном пользовательском каталоге.

### 🛡️ Расширенные возможности

- **Работа без зависимостей** — может быть упакован в один исполняемый файл, не требует установки Python.
- **Интеллектуальное управление портами** — автоматическое обнаружение занятого порта с интерактивными вариантами решения.
- **Горячий перезапуск сервисов** — поддержка отдельного перезапуска одного сервиса без влияния на другие.
- **Отслеживание ошибок** — возврат подробной информации о стеке ошибок, помогающей AI самостоятельно диагностировать и исправлять проблемы.
- **Защита предохранителем** — встроенные механизмы повторных попыток и предохранителя для предотвращения влияния сбойных сервисов на общую стабильность.

### 🚀 Оптимизация производительности

- **Интеллектуальная система кэширования** — автоматическое кэширование больших результатов, поддержка двух уровней: память и файлы.
- **Потоковый поиск** — быстрый поиск ключевых слов в больших файлах с постоянным потреблением памяти.
- **Поэтапное получение** — поддержка получения больших результатов по частям по требованию, избегая единовременной передачи слишком большого объёма данных.
- **Точное позиционирование** — быстрое получение контекста указанной строки.

## 🚀 Быстрый старт

### Предварительные требования

- **Среда выполнения**:
  - Использование исполняемого файла: без зависимостей.
  - Запуск из исходного кода: Python 3.8+.

### 1️⃣ Загрузка сервиса

#### Способ 1: Загрузка исполняемого файла (рекомендуется)

Скачайте исполняемый файл для вашей платформы из [Releases](https://github.com/WongJingGitt/mcp_bridge_server/releases):

- **Windows**: `mcp-bridge-server.exe`
- **macOS**: `mcp-bridge-server-macos`
- **Linux**: `mcp-bridge-server-linux`

#### Способ 2: Клонирование исходного кода

```bash
git clone https://github.com/WongJingGitt/mcp_bridge_server.git
cd mcp_bridge_server
pip install -r requirements.txt
```

### 2️⃣ Запуск сервиса

#### Использование скрипта запуска (рекомендуется)

<details>
<summary><b>Пользователи Windows</b></summary>

```bash
# Дважды щёлкните или выполните в командной строке
start.bat
```

```

Выберите способ запуска:
  1. Запуск по умолчанию (порт 3849, интерактивная обработка занятости порта)
  2. Автоматическая обработка занятости порта (принудительное завершение процесса)

  5. Выход
```
</details>

<details>
<summary><b>Пользователи Linux/Mac</b></summary>

```bash
# Предоставить права на выполнение (первый раз)

# Запустить
./start.sh
```
</details>

#### Прямой запуск (для разработчиков)

```bash
# Запуск по умолчанию (порт 3849)
python utils/mcp_bridge.py

# Автоматическая обработка занятости порта
python utils/mcp_bridge.py --auto-kill-port

# Использовать пользовательский порт
python utils/mcp_bridge.py --port 8080

# Комбинированные параметры
python utils/mcp_bridge.py --port 8080 --auto-kill-port
```

**Параметры командной строки**:

| Параметр | Описание | Значение по умолчанию |
|----------|----------|------------------------|
| `--port PORT` | Указать номер порта | 3849 |
| `--auto-kill-port` | Автоматически завершить процесс, занимающий порт | false |
| `--config PATH` | Указать путь к файлу конфигурации | Системный по умолчанию |

**Переменные окружения**:

| Переменная | Описание |
|------------|----------|
| `MCP_AUTO_KILL_PORT=true` | Автоматическая обработка занятости порта |
| `MCP_CONFIG_PATH=/path/to/config` | Путь к файлу конфигурации |

#### Обработка занятости порта

При первом запуске автоматически проверяется занятость порта:

```

⚠️  Порт 3849 уже занят
   Процесс: python.exe (PID: 12345)

Пожалуйста, выберите действие:
  1. Завершить процесс и продолжить
  2. Использовать другой порт
  3. Выйти из программы

Введите опцию (1/2/3): 
```

Подробное описание см. в [документации по управлению портами](docs/PORT_MANAGEMENT.md).


## ⚙️ Руководство по настройке

Это **ключевой шаг** использования проекта. Вам нужно указать мостовому сервису, где найти и как запустить ваши MCP-инструменты.

### Расположение файла конфигурации

Автоматически создаётся после первого запуска:

| Операционная система | Путь | Быстрый доступ |
|----------------------|------|----------------|
| **Windows** | `%APPDATA%\mcp-bridge\config\mcp-config.json` | Введите `%APPDATA%` в адресной строке проводника |
| **macOS** | `~/Library/Application Support/mcp-bridge/config/mcp-config.json` | Finder → Переход → Переход к папке |
| **Linux** | `~/.config/mcp-bridge/config/mcp-config.json` | Терминал `cd ~/.config/mcp-bridge/config` |

### Структура файла конфигурации

Откройте `mcp-config.json`, вы увидите структуру по умолчанию:

```json
{
  "mcpServers": {
    "example_service": {
      "enabled": true,
      "command": "path/to/your/mcp/server/executable",
      "args": ["--port", "8080"],
      "description": "Это пример сервиса, замените его на свою конфигурацию",
      "env": {}
    }
  }
}
```

### Примеры конфигурации

#### Пример 1: Инструмент файловой системы

```json
{
  "mcpServers": {
    "filesystem": {
      "enabled": true,
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "C:\\Users\\YourName\\Documents"],
      "description": "Предоставляет доступ к файловой системе, может читать и записывать файлы в указанном каталоге"
    }
  }
}
```

#### Пример 2: Управление репозиторием Git

```json
{
  "mcpServers": {
    "git": {
      "enabled": true,
      "command": "uvx",
      "args": ["mcp-server-git", "--repository", "C:\\myrepo"],
      "description": "Управление репозиторием Git, просмотр истории коммитов, веток, различий и т.д."
    }
  }
}
```

#### Пример 3: Конфигурация нескольких сервисов

```json
{
  "mcpServers": {
    "filesystem": {
      "enabled": true,
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:\\data"],
      "description": "Инструмент доступа к файловой системе"
    },
    "weather": {
      "enabled": true,
      "command": "python",
      "args": ["C:\\tools\\weather_server.py"],
      "description": "Предоставляет информацию о текущей погоде и прогноз на будущее",
      "env": {
        "API_KEY": "your_api_key_here"
      }
    },
    "calculator": {
      "enabled": false,
      "command": "C:\\tools\\calculator.exe",
      "args": [],
      "description": "Выполняет сложные математические вычисления и оценку выражений"
    }
  }
}
```

### Описание полей

| Поле | Обязательно | Тип | Описание |
|------|-------------|-----|----------|
| **Имя сервиса** (например, `"filesystem"`) | ✅ | string | Уникальный идентификатор сервиса, браузерное расширение распознаёт сервис по этому имени |
| `enabled` | ❌ | boolean | Включён ли сервис (по умолчанию true) |
| `command` | ✅ | string | Команда запуска (`python`, `node`, `npx`, путь к исполняемому файлу и т.д.) |
| `args` | ❌ | array | Список аргументов, передаваемых команде; каждый аргумент — отдельная строка |
| `description` | ✅ | string | **Важно!** Описание функциональности сервиса; AI-модель на основе этого решает, использовать ли сервис, пишите чётко и точно |
| `env` | ❌ | object | Пары ключ-значение переменных окружения для дополнительных переменных окружения процесса сервиса |

### Применение новой конфигурации

После изменения конфигурации есть два способа применить её:

#### Способ 1: Перезапуск сервиса

```bash
# Остановить сервис (Ctrl+C)
# Повторно запустить скрипт запуска
./start.sh  # или start.bat
```

#### Способ 2: Горячая перезагрузка (рекомендуется)

```bash
# Перезагрузить все сервисы
curl -X POST http://localhost:3849/reload

# Или использовать страницу настроек браузерного расширения
# Options → Конфигурация сервисов → Сохранить и перезагрузить сервисы
```

#### Способ 3: Отдельный перезапуск сервиса

```bash
curl -X POST http://localhost:3849/restart-server \
  -H "Content-Type: application/json" \
  -d '{"serverName": "filesystem"}'
```

Подробное описание см. в [руководстве по перезапуску сервисов](docs/RESTART_SERVER_GUIDE.md).

### Основные интерфейсы

#### Интерфейс выполнения инструментов

#### `GET /health`
*   **Функция**: Проверка работоспособности.
*   **Возврат**: `{ "status": "ok", "timestamp": 1678886400000 }`

#### `GET /tools`
*   **Функция**: **(Обнаружение первого уровня)** Получить список всех загруженных **сервисов** и их описания.
*   **Возврат**:
    ```json
    {
      "success": true,
      "services": [
        { "name": "weather_service", "description": "..." },
        { "name": "calculator_service", "description": "..." }
      ]
    }
    ```

#### `GET /tools?serverName=<name>`
*   **Функция**: **(Обнаружение второго уровня)** По имени сервиса получить подробную информацию обо всех конкретных **инструментах** этого сервиса.
*   **Параметры**: `serverName` — имя сервиса, определённое в файле конфигурации.
*   **Возврат**:
    ```json
    {
      "success": true,
      "tools": [
        {
          "name": "get_current_weather",
          "description": "Получить текущую погоду в указанном городе",
          "parameters": { /* JSON Schema */ },
          "serverName": "weather_service"
        }
      ]
    }
    ```

#### `POST /execute`
*   **Функция**: Выполнить указанный инструмент.
*   **Тело запроса**: `{ "name": "tool_name", "arguments": { "param": "value" } }`
*   **Успешный возврат**: `{ "success": true, "result": [...] }`
*   **Возврат при ошибке**:
    ```json
    {
      "detail": {
        "error": "Сообщение об ошибке",
        "type": "ErrorType",
        "traceback": "Полный стек вызовов Python"
      }
    }
    ```
    > **Расширенная обработка ошибок**: начиная с v1.1, при неудачном выполнении возвращается подробная информация об ошибке, включая тип ошибки и полный стек вызовов Python, что помогает быстро локализовать проблему. Браузерное расширение отображает эту информацию AI-модели, чтобы она могла проанализировать причину ошибки и попытаться исправить её.

#### `POST /reload`
*   **Функция**: Перезагрузить и инициализировать все сервисы из файла конфигурации. После изменения `mcp-config.json` вызов этого интерфейса применяет конфигурацию без перезапуска основного сервиса.
*   **Возврат**: `{ "success": true, "message": "Конфигурация перезагружена" }`

#### `POST /config`
*   **Функция**: Напрямую обновить содержимое файла `mcp-config.json` через API и автоматически выполнить перезагрузку.
*   **Тело запроса**: `{ "config": { "mcpServers": { ... } } }`
*   **Возврат**: `{ "success": true, "message": "Конфигурация сохранена и перезагружена" }`

### Интерфейсы управления сервисами

#### `POST /restart-server`
*   **Функция**: Перезапустить указанный отдельный сервис, не влияя на другие сервисы.
*   **Тело запроса**:
    ```json
    {
      "serverName": "weather_service",
      "config": { /* опционально, предоставить новую конфигурацию */ }
    }
    ```
*   **Возврат**: `{ "success": true, "message": "Сервис xxx перезапущен", "toolCount": 5 }`
*   **Подробная документация**: см. [руководство по перезапуску сервисов](docs/RESTART_SERVER_GUIDE.md)

#### `POST /shutdown-server`
*   **Функция**: Закрыть указанный сервис.
*   **Тело запроса**: `{ "serverName": "weather_service" }`
*   **Возврат**: `{ "success": true, "message": "Сервис xxx закрыт" }`

#### `POST /reset-history`
*   **Функция**: Сбросить счётчики неудачных вызовов для всех инструментов.
*   **Возврат**: `{ "success": true, "message": "История вызовов сброшена" }`

### Интерфейсы управления кэшем

#### `GET /result/{cache_id}`
*   **Функция**: Получить содержимое кэшированного результата (с поддержкой поэтапного получения).
*   **Параметры**:
    - `cache_id` — ID кэша (получается из результата выполнения инструмента)
    - `start` — опционально, начальная позиция символа (по умолчанию 0)
    - `end` — опционально, конечная позиция символа (по умолчанию все)
*   **Возврат**:
    ```json
    {
      "success": true,
      "result": "Содержимое кэша",
      "metadata": {
        "total_length": 30520,
        "start": 0,
        "end": 10000,
        "has_more": true
      }
    }
    ```

#### `POST /search-cache`
*   **Функция**: Поиск ключевого слова в кэшированном содержимом (потоковая обработка, оптимизация производительности).
*   **Тело запроса**:
    ```json
    {
      "cache_id": "ID кэша",
      "keyword": "Ключевое слово для поиска",
      "case_sensitive": false,
      "max_results": 50
    }
    ```
*   **Возврат**:
    ```json
    {
      "success": true,
      "result": {
        "keyword": "Ключевое слово для поиска",
        "total_matches": 15,
        "matches": [
          {
            "line": 23,
            "column": 45,
            "content": "...фрагмент совпавшего содержимого..."
          }
        ],
        "truncated": false
      }
    }
    ```
*   **Особенности производительности**:
    - Потоковое чтение, постоянное потребление памяти (~10 МБ)
    - Поддержка файлов любого размера
    - Поиск в файле 10 МБ < 100 мс

#### `POST /get-cache-context`
*   **Функция**: Получить контекст указанной строки в кэше.
*   **Тело запроса**:
    ```json
    {
      "cache_id": "ID кэша",
      "line_num": 23,
      "context_lines": 5
    }
    ```
*   **Возврат**:
    ```json
    {
      "success": true,
      "result": {
        "target_line": 23,
        "context_start": 18,
        "context_end": 28,
        "total_lines": 500,
        "content": "...содержимое контекста..."
      }
    }
    ```

### Описание системы кэширования

Когда результат, возвращаемый инструментом, превышает порог (по умолчанию 1000 байт), сервер автоматически кэширует результат и возвращает ссылку на кэш:

```json
{
  "success": true,
  "result_type": "cached_reference",
  "cache_id": "uuid-string",
  "cache_type": "memory",  // или "file"
  "total_size": 30520,
  "message": "Результат слишком большой, закэширован"
}
```

**Стратегия кэширования**:
- **Кэш в памяти**: результат ≤ 10 КБ, быстрый доступ.
- **Файловый кэш**: результат > 10 КБ, экономия памяти.
- **Автоматическое истечение**: TTL = 5 минут (настраивается).
- **Вытеснение LRU**: кэш в памяти хранит не более 100 элементов.

**Параметры конфигурации** (задаются в конфигурации сервиса):
```json
{
  "mcpServers": {
    "your_service": {
      "max_output_bytes": 1000,        // порог срабатывания кэширования
      "cache_large_results": true,      // включить кэширование
      "result_cache_ttl": 300,          // время жизни кэша (секунды)
      "max_memory_cache_size": 10240    // порог кэша в памяти (байты)
    }
  }
}
```

**Сценарии использования**:
1. **Чтение больших файлов** — чтение файлов в несколько МБ, сначала поиск, затем точное получение.
2. **Анализ логов** — поиск информации об ошибках в больших логах.
3. **Запросы данных** — поэтапный показ при возврате большого объёма данных.
