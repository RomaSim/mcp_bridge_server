# Управление портами

## Обзор функции

MCP Bridge Server теперь обладает интеллектуальной функцией обнаружения и управления портами, которая позволяет проверять занятость порта перед запуском и предлагает несколько элегантных способов решения проблемы.

## Способы запуска

### 1. Запуск по умолчанию (интерактивный)

```bash
python utils/mcp_bridge.py
```

**Поведение**:
- Проверяет, занят ли порт по умолчанию 3849.
- Если порт занят, отображает информацию о процессе и предлагает три варианта:
  - `1` — завершить процесс и продолжить
  - `2` — использовать другой порт
  - `3` — выйти из программы

**Пример вывода**:
```
MCP Bridge Server v1.0.0
Проверка порта 3849...

⚠️  Порт 3849 уже занят
   Процесс: python.exe (PID: 12345)

Пожалуйста, выберите действие:
  1. Завершить процесс и продолжить
  2. Использовать другой порт
  3. Выйти из программы

Введите опцию (1/2/3): 
```

### 2. Автоматическое завершение процесса

```bash
# Способ 1: использовать параметр командной строки
python utils/mcp_bridge.py --auto-kill-port

# Способ 2: использовать переменную окружения
set MCP_AUTO_KILL_PORT=true  # Windows
export MCP_AUTO_KILL_PORT=true  # Linux/Mac
python utils/mcp_bridge.py
```

**Поведение**:
- Автоматически завершает процесс, занимающий порт, без ручного подтверждения.
- Подходит для автоматизированного развёртывания и сред CI/CD.

### 3. Указание другого порта

```bash
python utils/mcp_bridge.py --port 8080
```

**Поведение**:
- Запускается на указанном порту.
- Если этот порт тоже занят, всё равно срабатывает процедура проверки порта.

### 4. Комбинированное использование

```bash
# Запуск на порту 8080, если занят — автоматически завершить процесс
python utils/mcp_bridge.py --port 8080 --auto-kill-port

# Использовать пользовательский файл конфигурации и порт
python utils/mcp_bridge.py --port 8080 --config /path/to/config.json
```

## Параметры командной строки

| Параметр | Описание | Значение по умолчанию |
|----------|----------|------------------------|
| `--port PORT` | Указать порт сервера | 3849 |
| `--auto-kill-port` | Автоматически завершать занимающий процесс | false |
| `--config PATH` | Указать путь к файлу конфигурации | Системный путь по умолчанию |

## Переменные окружения

| Имя переменной | Описание | Допустимые значения |
|----------------|----------|---------------------|
| `MCP_AUTO_KILL_PORT` | Автоматически завершать занимающий процесс | true, 1, yes |
| `MCP_CONFIG_PATH` | Путь к файлу конфигурации | Путь к файлу |

## Механизм обнаружения порта

### Система Windows

Используются команды `netstat` и `tasklist`:
```bash
netstat -ano | findstr :3849
tasklist /FI "PID eq 12345"
```

Завершение процесса:
```bash
taskkill /F /PID 12345
```

### Система Linux/Mac

Используются команды `lsof` и `ps`:
```bash
lsof -i :3849 -t
ps -p 12345 -o comm=
```

Завершение процесса:
```bash
kill -9 12345
```

## Обработка ошибок

### Порт занят, но не удаётся получить информацию о процессе

```
⚠️  Порт 3849 уже занят
   Процесс: Unknown (PID: Unknown)
```

**Причина**: возможно, недостаточно прав или системные команды недоступны.

**Решение**:
- Windows: запустить от имени администратора.
- Linux/Mac: использовать `sudo` или убедиться в наличии достаточных прав.

### Не удаётся завершить процесс

```
✗ Не удалось завершить процесс
```

**Причина**:
- Недостаточно прав.
- Процесс защищён.
- Процесс уже завершён, но порт не освобождён.

**Решение**:
- Использовать права администратора/root.
- Завершить процесс вручную.
- Подождать некоторое время и повторить попытку.

### Процесс завершён, но порт всё ещё занят

```
✗ Порт 3849 всё ещё занят
```

**Причина**: системе нужно время для освобождения порта.

**Решение**:
- Подождать несколько секунд и повторить.
- Проверить, не занят ли порт другим процессом.
- Перезапустить сетевую службу.

## Соображения безопасности

### 1. Контроль прав

- **Не используйте `--auto-kill-port` без разбора**, особенно на общих серверах.
- Убедитесь, что завершаете только те процессы, которыми имеете право управлять.
- В производственной среде используйте автоматическое завершение с осторожностью.

### 2. Проверка процесса

В автоматизированных скриптах рекомендуется сначала проверять информацию о процессе:

```bash
# Проверить, является ли процесс вашим
python utils/mcp_bridge.py
# После ручного подтверждения использовать --auto-kill-port
```

### 3. Ведение журнала

Все операции с портами выводятся в консоль, рекомендуется:

```bash
# Записывать журнал
python utils/mcp_bridge.py --auto-kill-port 2>&1 | tee mcp-server.log
```

## Лучшие практики

### ✅ Рекомендуется

1. **Среда разработки**: использовать интерактивный режим с ручным управлением.
2. **Тестовая среда**: использовать `--auto-kill-port` для быстрых итераций.
3. **Производственная среда**: использовать переменные окружения + управление конфигурацией.
4. **Мониторинг портов**: регулярно проверять занятость портов.
5. **Ведение журналов**: сохранять журналы запуска для диагностики проблем.

### ❌ Не рекомендуется

1. Слепо использовать `--auto-kill-port`, не зная, какой процесс занимает порт.
2. Использовать автоматическое завершение на общих серверах.
3. Игнорировать предупреждения о занятости порта и принудительно запускаться.
4. Не вести журналы и не фиксировать информацию о процессах.

## Устранение неполадок

### Проблема: постоянно сообщается, что порт занят

**Шаги проверки**:

1. Проверьте, не работает ли старый процесс.
   ```bash
   # Windows
   netstat -ano | findstr :3849
   
   # Linux/Mac
   lsof -i :3849
   ```

2. Завершите процесс вручную.
   ```bash
   # Windows
   taskkill /F /PID <PID>
   
   # Linux/Mac
   kill -9 <PID>
   ```

3. Проверьте настройки брандмауэра.

4. Попробуйте использовать другой порт.

### Проблема: функция автоматического завершения не работает

**Шаги проверки**:

1. Убедитесь в наличии достаточных прав.
2. Проверьте доступность системных команд (netstat/lsof).
3. Просмотрите журнал ошибок.
4. Попробуйте завершить процесс вручную.

## Примеры скриптов

### Скрипт запуска (Windows)

```batch
@echo off
echo Starting MCP Bridge Server...

REM Проверка, не запущен ли уже
netstat -ano | findstr :3849 > nul
if %errorlevel%==0 (
    echo Port 3849 is in use, killing process...
    for /f "tokens=5" %%a in ('netstat -ano ^| findstr :3849') do (
        taskkill /F /PID %%a
    )
    timeout /t 2 /nobreak > nul
)

REM Запуск сервиса
python utils/mcp_bridge.py --auto-kill-port

pause
```

### Скрипт запуска (Linux/Mac)

```bash
#!/bin/bash

echo "Starting MCP Bridge Server..."

# Проверка, не запущен ли уже
PID=$(lsof -ti :3849)
if [ ! -z "$PID" ]; then
    echo "Port 3849 is in use by PID $PID, killing process..."
    kill -9 $PID
    sleep 2
fi

# Запуск сервиса
python3 utils/mcp_bridge.py --auto-kill-port
```

### Скрипт демона

```bash
#!/bin/bash

while true; do
    echo "Starting MCP Bridge Server at $(date)"
    python3 utils/mcp_bridge.py --auto-kill-port
    
    echo "Server stopped at $(date), restarting in 5 seconds..."
    sleep 5
done
```
